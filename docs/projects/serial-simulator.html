RS232 통신 모의 프로그램

Python·PyQt로 장비 연동 시험을 위한 통신 모의 프로그램을 개발했습니다. 통신 설정부터 송수신과 로그 확인까지의 흐름을 설계했습니다.

  • Python
  • PyQt5
  • MVVM
  • pyserial
  • SQLite
역할
UX/UI · 소프트웨어 구조 설계 · 통신·데이터 처리 · 오류 분석
상태
개발 · 저작권 등록 완료
핵심 작업
화면·통신·데이터를 연결한 데스크톱 도구
구조도동작 흐름설계 선택과 코드확인 범위

Architecture / Flow

화면·통신·저장을 나눈 구성 개념도

SVG 원본Mermaid 소스

해결할 문제

장비 통신을 설정하고 데이터를 보내고 받는 과정에서, 입력·연결 상태·실행 결과를 함께 확인할 도구가 필요했습니다. 사용자의 조작과 통신 결과를 한 데스크톱 프로그램으로 연결했습니다.

본인 역할

UX/UI와 소프트웨어 아키텍처를 설계하고 통신·데이터 처리를 구현했습니다. 활동·시퀀스·클래스 다이어그램과 발표 자료를 준비해 설계 선택과 동작 흐름을 설명했습니다.

설계 선택

MVVM과 계층화한 Model을 적용했습니다. Dispatcher는 비동기 통신을, Repository·DAO는 SQLite 데이터 접근을 담당하도록 구성했습니다. 로그 창은 분리·재결합할 수 있도록 모듈화했습니다.

통신과 오류 분석

pyserial의 포트 열기·닫기와 읽기·쓰기 동작을 확인했습니다. 로그로 송수신·프레임 처리·재시도·ACK 수신 흐름을 추적하고, 포트 핸들 오류와 중복 ACK 발생 시점을 분석했습니다.

Follow the data

동작 흐름을 따라가면

  1. 화면에서 작업 입력

    PyQt 화면에서 통신과 데이터 작업을 입력하고 ViewModel을 통해 처리합니다.

  2. 통신과 저장의 책임 분리

    비동기 통신은 Dispatcher, 데이터 접근은 Repository/DAO 구조로 구분했습니다.

  3. 로그로 상태 확인

    송신·수신·재전송·ACK 기록을 확인하며 포트 핸들 오류와 중복 ACK를 분석했습니다.

Engineering decisions

구현에서 읽을 수 있는 설계 선택

UI와 처리 책임 분리

MVVM과 계층 구조를 적용해 화면 동작과 통신·데이터 처리의 역할을 구분했습니다.

고려할 점 컴포넌트 간 상태와 이벤트의 전달 규칙을 일관되게 유지해야 합니다.

통신 흐름을 관찰 가능한 기록으로 만들기

송수신·ACK·재전송 로그와 분리·결합 가능한 로그 창을 구현했습니다.

고려할 점 송수신과 재전송 기록을 함께 읽어야 포트 연결 문제와 응답 처리 문제를 구분할 수 있습니다.

확인 범위와 남은 과제

  • 업무 산출물의 전체 소스, 내부 프로토콜·원시 로그·체계 세부 구성은 공개하지 않습니다.
  • 저작권 등록된 프로그램이며, 이 페이지는 설계·구현 기여를 소개합니다.
